# Как вносить изменения

Этот репозиторий хранит статический сайт-портфолио. Изменения должны быть небольшими, проверяемыми и без приватных данных.

## Перед началом

1. Проверь состояние репозитория:

```bash
git status
```

2. Установи зависимости, если проект запускается впервые:

```bash
npm.cmd install
```

3. Запусти локальную разработку:

```bash
npm.cmd run dev -- --host 127.0.0.1 --port 4323
```

## Контент

- Опыт добавляется в `src/content/experience`.
- Кейсы добавляются в `src/content/projects`.
- Основные данные профиля, контакты, навыки, метрики и ссылки на артефакты хранятся в `src/data/profile.ts`.
- Изображения лежат в `public/images`.
- Политика конфиденциальности и согласие находятся в `src/pages/privacy.astro` и `src/pages/consent.astro`.

Для новых кейсов заполняй `title`, `category`, `role`, `order`, `stack`, `links` и `outcomes`.

## Качество

Перед публикацией запусти:

```bash
npm.cmd run build
```

Сборка должна проходить без ошибок, предупреждений и подсказок.

Минимальный smoke-проход:

- нет горизонтального скролла на desktop и mobile;
- хедер, CTA, карточки и форма не перекрывают текст;
- мобильный хедер показывает вкладки `Диплом`, `Опыт`, `Артефакты`, `Мои проекты`, `Связь`;
- переключатель темы работает плавно;
- форма связи изначально не показывает уведомления;
- при ошибочных данных показывается только ошибка;
- при корректной отправке показывается только успешное сообщение;
- ссылки на GitHub, VK, PDF диплома, политику, согласие и Google Drive открываются по актуальным адресам.

## Безопасность

Не добавляй в репозиторий:

- пароли;
- токены;
- приватные ключи;
- архивы с личными данными;
- `.codex`, логи, временные дампы и файлы локальной авторизации;
- приватные репозитории и закрытые ссылки.

Также не коммить `dist`, `node_modules`, `.astro`, `.agent-work`, `.env` и локальные бэкапы.

## Версии и changelog

Версия проекта хранится в `package.json` и отражается в GitHub release.

Перед релизом:

1. Обнови `CHANGELOG.md`.
2. Обнови версию в `package.json` и `package-lock.json`.
3. Проверь `README.md` и `CONTRIBUTING.md`.
4. Запусти `npm.cmd run build`.
5. Сделай коммит с понятным русским сообщением.
6. Создай тег и GitHub release.

## Публикация

Публикация идет через GitHub Pages после пуша в `master`. Workflow находится в `.github/workflows/deploy.yml` и собирает статический Astro-сайт в `dist`.

Перед пушем проверь, что в коммит не попали служебные файлы и что сборка завершилась чисто.

## Коммиты

Коммит должен описывать, что изменилось и зачем. Для этого проекта предпочтительны русские сообщения коммитов.
